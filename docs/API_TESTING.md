# API Testing With Bruno

The repository includes a Git-friendly [Bruno](https://www.usebruno.com/) collection for validating the Loopin backend against local and staging environments.

## Collection Location

```text
api-tests/bruno
```

Open Bruno, choose **Open Collection**, and select the `api-tests/bruno` directory.

## Environments

The collection includes two example environments:

| Environment | Base URL |
| --- | --- |
| Local | `http://localhost:8080/api` |
| Staging | `https://staging-api.loopin.example/api` |

Both environments intentionally use placeholder values only. Replace `auth_token`, `google_id_token`, IDs, and staging hostnames in your local Bruno workspace before sending requests. Do not commit real JWTs, Google ID tokens, user credentials, or production URLs.

## Authentication Workflow

Most write endpoints require:

```http
Authorization: Bearer {{auth_token}}
```

To test authenticated endpoints:

1. Run `Auth / Register User` if you need a local seed user record.
2. Run `Auth / Google Login` with a real Google ID token generated by a trusted frontend or test auth flow.
3. Copy the `token` value from the response into the active Bruno environment as `auth_token`.
4. Send Events, Groups, Join Requests, and Chat requests.

The committed collection stores `{{auth_token}}` as a placeholder, not a real JWT.

## Included Request Groups

| Group | Purpose |
| --- | --- |
| Auth | User registration and Google login examples. |
| Events | List, inspect, create, update, delete, and recommended event examples. |
| Groups | Create, inspect, update, and status-change event group examples. |
| Join Requests | Submit, review, approve, reject, and delete group join requests. |
| Chat | List and send persisted group messages through the REST chat endpoint. |

## Validation Notes

The application is served under the `/api` context path, so environment `base_url` values include `/api`.

Public `GET /events/**` and `GET /groups/**` endpoints do not require authentication. Authenticated write endpoints, recommendations, profiles, join requests, and chat endpoints require a valid bearer token.

Group and event resource paths use public UUIDs except the REST chat controller, which currently expects the internal numeric group id in `/groups/{groupId}/messages`.

## Safe Git Hygiene

Before committing API test changes, run your normal secret scanner or search the API test files for JWT-shaped values, Google tokens, API keys, private keys, and literal passwords.

Any matches should be reviewed carefully. Placeholder values such as `<paste-google-id-token-locally>` and `{{auth_token}}` are safe to commit.
